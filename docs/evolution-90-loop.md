# Evolution loop with a 90% target

The canonical runner accepts `--target-win-rate` as a probability strictly
between 0 and 1. Its default remains `0.95`; set `--target-win-rate 0.90` to
use a 90% outright-win target. Validation still requires the observed rate to
be strictly above the target. Promotion still requires a fresh confirmation
batch whose one-sided exact binomial lower bound is strictly above it. The
existing alpha-spending schedule remains unchanged. Capped tables are not
wins, and Wilson intervals remain descriptive 95% intervals.

## Importing prior training archives

Repeat `--archive-checkpoint PATH` to import the complete union of each
checkpoint's `training_opponents` and `hall_of_fame` genomes. This import only
reads those ID lists and their referenced canonical genomes. It does not read
fitness, validation results, confirmation results, champion records, or
generation history. Imported policies join training opponent sampling and
remain archived; they do not become active seed candidates. Use the separate
`--seed-genomes PATH` option for seed candidates.

If source checkpoints reuse an ID for different family/parameter records, the
runner assigns source-scoped aliases such as `policy-x@archive-0` and
`policy-x@archive-1`. Before constructing policies, it restores each alias to
the original source policy ID, preserving ID-dependent action randomness. An
optional `--archive-policy-ids PATH` JSON object maps already-aliased records
to their original IDs. An archived policy that reuses one of this run's fixed
genome IDs (for example `train-opponent-0000` from a run with another seed)
for a different policy gets the alias `train-opponent-0000@archive` when all
sources agree on it, or source-scoped aliases when they disagree. Conflicting aliases, missing genomes, duplicate IDs
within a source pool, and invalid policy-ID mappings fail closed.

The config and checkpoint freeze the archive union, source projection hashes,
per-genome lineage and provenance, original policy IDs, and archive content
hashes. Resume rereads and reprojects each source; a changed training/HOF
archive or changed mapping is rejected. The source projection hash covers
training/HOF membership and referenced genomes only, so heldout fitness is not
part of archive import or seed selection. Validation and confirmation pools
are generated by the existing independent fixed-pool path and are unchanged by
archive import.

## Reproducible new-run command

This starts a new 90% search using the complete training/HOF union from the
November 2 successor and V4 checkpoints. The source list order is part of the
frozen alias/provenance snapshot.

```sh
.venv/bin/python -m pokerbot.evolution run \
  --output-dir reports/evolution-90-archive-union-v1 \
  --population 16 --generations 1 \
  --target-win-rate 0.90 \
  --archive-checkpoint reports/evolution-next-20261102/checkpoint.json \
  --archive-checkpoint reports/evolution-v4/checkpoint.json \
  --evaluation-namespace evolution-90-archive-union-v1 \
  --matches 128 --validation-matches 128 --confirmation-matches 512 \
  --seed 20261103 --workers 4
```

Use the same experiment options with `--resume` for subsequent chunks. A
separate training-only seed file can be added with `--seed-genomes PATH`; its
genomes remain separate from the imported opponent archive.
